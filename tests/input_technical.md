# 数据库索引入门

数据库索引是一种用于加速数据检索的数据结构。没有索引时，数据库必须做全表扫描，逐行比对，当表很大时这会非常慢。

最常见的索引结构是 B+ 树。B+ 树是一种平衡多路搜索树，所有数据都存放在叶子节点，并且叶子节点之间通过指针相连，因此范围查询非常高效。

聚簇索引与非聚簇索引是不同的概念。聚簇索引决定了数据行在磁盘上的物理存储顺序，一个表只能有一个聚簇索引；非聚簇索引的叶子节点保存的是指向数据行的指针（或聚簇键），因此通过非聚簇索引查找往往需要一次"回表"。

索引虽然能加速查询，但并不是越多越好。每一个索引都会占用额外的存储空间，并且在插入、更新、删除数据时需要同步维护，从而降低写性能。这是一个典型的空间换时间、读快写慢的权衡。

最左前缀原则是关于复合索引的重要规则。对于 (a, b, c) 这样的复合索引，查询只有在条件命中了最左侧的列（如 a，或 a 和 b）时才能有效利用该索引；如果跳过最左列（例如只查 b 和 c），索引通常就失效了。

覆盖索引可以避免回表。如果一条查询所需要的所有字段都已经包含在某一个索引中，数据库就不需要再回到主表去取数据，从而进一步提升性能。

索引失效还有一些常见诱因，比如对索引列做函数运算、使用隐式类型转换、或者用通配符开头的 LIKE 查询（如 '%abc'），这些写法都会让优化器放弃使用索引。

最后，选择索引列时应优先为高区分度、频繁出现在 WHERE、JOIN 和 ORDER BY 中的列建立索引，而很少出现在过滤条件中的低区分度列则不适合建索引。
